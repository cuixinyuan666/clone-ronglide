## §1 0x1003f170 衔接关系 [A]

### §1.1 入口与签名

`sub_1003f170(W, mode) -> void`；`ret 8`（2 dword 入参；callee 清栈）

调用点 (来自 `core_1002c1d0.txt:91-97`)：
```
P==0x0B (11): push 1; push edi; call 0x1003f170   ; 1002c2c6
P==0x0C (12): push 2; push edi; call 0x1003f170   ; 1002c2d0
```

入参语义：arg1 = edi = W 持有指针（[edi]=W），arg2 = mode ∈ {1, 2}。
- mode=1 → 顶向
- mode=2 → 底向
（与 0x1004b1e0 / 0x1004f430 的 mode 语义对齐 — docs/20 §6 已确认）

### §1.2 反汇编规模

- 11191 insn ｜ 1288 基本块 ｜ 481 条件 ｜ 4 conflicts
- 跨度 0x1003f170..0x1004b1cf（多 ret：10049169 是中间出口，1004b1cf 是最终 ret 8）
- 栈帧：`sub esp, 0x8b4`（2204 字节大栈），prologue 即零 W+0x88/0x90/0x8c（说明 W 容器内 3 个 4 字节槽为该函数私有状态）

### §1.3 工具调用密度（`f_1003f170.txt`）

| 目标地址 | 次数 | 语义（来自 docs/21 §7 + 第二批助手函数字节级索引） |
| --- | --- | --- |
| 0x1006a830 | 1180 | `vector::iterator::operator*` |
| 0x1003d720 | 75 | `iterator++`（步进 0x28） |
| 0x1003d750 | 61 | `iterator--`（步进 0x28） |
| 0x1003f0d0 | 58 | `m0.begin() + idx` |
| 0x1006a720 | 28 | `push_back` 0x28 元素 |
| 0x10069540 | 16 | 读 `+0x14==-1` 判据 |
| 0x1006a890 | 14 | `pop_back` 0x28 |

**判断** [A]：f170 **重度迭代 m5 容器**（0x28 元素，1180 次 operator*），主要操作 push_back/pop_back/erase 0x28；m0 容器只通过 begin+idx 取迭代器。它**不像 db40 那样做候选端点生成**，而是**对已存在的 m5 记录做方向化分类与剔除**（与 e200 配合）。

### §1.4 尾块（1004b150..1004b1c5）[A]

清空 m0 所有元素 `+0x20 = 0`（迭代器检查回调 `0x1006f194`），然后 `ret 8`。
即 f170 **改写 m0 端点戳**（与 a040 / eba0 / ef00 同构，见 docs/21 §5）。

## §2 P=51 全链重放骨架（见同目录 `chbi.py`）[A]

按 docs/20/21/22 的 [A] 级结论，P=51 全链顺序：
```
sub_1002c4b0(series, ctx, count, outD, iface):   ; 硬编码 P=51 入口
  → db40(w, count, bufA, bufB)                   ; 候选端点生成
  → e200(w)                                      ; 严格包含分型 (+0x14=±1)
  → a040(w)                                      ; 分型笔记录生成 (m5 容器)
  → eba0(w)                                      ; 按方向拆 ContA(W+0x20)/ContB(W+0x30)
  → ef00(w)                                      ; 全量复制 ContC(W+0x40)
  → iface->vtbl[1](0xEA62)                       ; 第二道授权门
  → 输出环：out[elem.bar-1] = (double)elem.+0x20, 若 +0x98==1 则 ×2
  → return 0
```

骨架文件: `tools/wnmr_py/chbi.py`（纯 Python 复刻，可运行单元测试桩）。

## §3 H_max/L_min 仲裁 #4 进展 [C]

**观察**：f170 调用的工具函数集中在 0x1006a830 (operator*) / 0x1003d720 (it++) / 0x1003d750 (it--)，
**未调用 0x1003d8a0**（m5 区间擦除，用于清零 m5 容器）。
而 db40 中 m5 由 a040 / eba0 / ef00 操作。
**因此 f170 不更新 m0 的 H_max/L_min，也不更新 db40 的 `[esp+0x28/0x2c]`**（那是 db40 内部栈帧）。

**结论 [C 待仲裁]**：H_max/L_min 不更新是 **db40 自身的实现选择**——它把 0 作为初始下界，
触发候选是单边比较（cond 17-25 段），不依赖上下界的动态更新。
这一设计减少了 db40 的栈帧压力（仅 0x174），但**把"方向判定"推到了 f170/b1e0/f430 这三个大函数里**。
因此"db40 内的 ebx>0 / ebx<=0 分流"在 f170 路径下被绕过——P=11/12 走 f170，db40 的 ebx/cond 1-16 不活跃。

**最终仲裁** [A]：docs/22 §3 表格的"ebx>0 / ebx<=0 路径"在 P=11/12 时**不执行**（dispatcher 跳过 db40 后的
cond 分流直接到 f170）；db40 在该路径下仅完成"候选端点生成"和 first-flag 控制（cond 17-25 段）。
**docs/22 §3.1-3.3 表格的"ebx>0 / ebx<=0 路径"是 P=21/22/31/32 专用语义**，P=11/12 与 P=51 都不走。

## §4 58560 点对拍方案（见同目录 `duipai.md`）[B]

数据集：`Dat/His/02/1/600000.1`（浦发银行 2017 年 1 分钟线，58560 条，36 字节/条）。

字段表（docs/2026-10-15 报告）：
- [+0x00..+0x03] int  time/offset
- [+0x04..+0x07] int  open (scaled)
- [+0x08..+0x0B] int  high
- [+0x0C..+0x0F] int  low
- [+0x10..+0x13] int  close
- [+0x14..+0x17] int  volume / amount
- [+0x18..+0x1B] int  open interest (or flag)
- [+0x1C..+0x23] float avg price (or extra)

**精度还原**：H/L 需除以 1000（价格精度 3 位小数）才能对应 db40 输入的 float。
