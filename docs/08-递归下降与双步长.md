## 二、递归下降反汇编(新工具)

### 2.1 为什么需要

线性扫描(`md.disasm` + `skipdata`)会把数据字节误判为指令,且遇到无法解码的字节后
对齐可能漂移。递归下降从**已知入口**(629 个函数入口 + PE 入口)出发,只沿真实控制流
(顺序、条件跳转、直接跳转、调用)推进。

### 2.2 结果对比

| 方法 | 指令数 | 说明 |
|---|---|---|
| 线性扫描(`skipdata`) | 142,887 | 含数据字节误判 |
| **递归下降** | **92,442** | 仅可达指令,边界可靠 |

> **局限**:递归下降**无法覆盖仅通过间接跳转(跳转表)到达的代码**(MSVC `switch` 常见)。
> 因此对"某函数是否写某偏移"这类**存在性**问题,需**两种方法交叉验证**(本批即如此)。

## 三、批 7 假设的证伪

### 3.1 假设回顾

> 批 7 建议:用递归下降重扫 `sub_1003F170`(11,169 条),"线性扫描可能因指令边界错位而漏检

### 3.2 检验结果

| `+0x08` | 2 | `0x1004ae43: add dword ptr [eax + 8], -0x28`（见 §4，非元素字段） |

## 四、`+0x08` 的唯一算术命中 —— 真相是 vector `pop_back`

### 4.1 命中指令

```
0x1004ae43: add dword ptr [eax + 8], -0x28     ; in sub_1003F170
0x1004af3e: add dword ptr [esi + 8], -0x28     ; in sub_1003F170
```

### 4.2 上下文

```asm
0x1004ae39: mov eax, dword ptr [esp + 0x8c8]   ; eax = W（上下文对象）
0x1004ae40: add eax, 0x50                       ; eax = W + 0x50   ← 成员 m[5]
0x1004ae43: add dword ptr [eax + 8], -0x28      ; (W+0x50)+8 -= 0x28
```

```asm
0x1004af29: mov esi, dword ptr [esp + 0x8c8]   ; esi = W
0x1004af30: add esi, 0x50                       ; esi = W + 0x50   ← 成员 m[5]
0x1004af35: call 0x1006a6e0                     ; vector 操作（析构/弹出）
0x1004af3a: test al, al
0x1004af3c: jne 0x1004af42
0x1004af3e: add dword ptr [esi + 8], -0x28      ; _Mylast -= 0x28
```

### 4.3 解读

`[eax+8]` 在此处 = **`W->m[5]._Mylast`**(成员 m[5] 位于 `W+0x50`,`_Mylast` 在其 +0x08),
`-0x28` = **一个元素的大小**。这是 **`pop_back` 的 `_Mylast -= sizeof(T)`**。

> **因此:`W->m[5]` 是「0x28 步长元素」的 vector。**
> 这与批 4 的结论「输入 bar 步长 0x28」完全吻合 —— 即批 4 所说的"输入 bar 数组"就是 `W->m[5]`。

## 五、🔑 关键发现:`sub_10056190` 同时迭代两种步长

### 5.1 两种迭代器并存

| 迭代器 | 位置 | 步长 | 推进方式 | 证据 |
|---|---|---|---|---|
| **iterA** | 帧偏移 −772/−768 | **0xA0** | `sub_1003d720`(`_Myptr += 0xA0`) | `0x1005a117: lea esi,[esp+0x68]; call 1003D720h` |
| **iterB** | 帧偏移 −808/−804 | **0x28**（待确认） | 见下 | 全局扫描 |

全局扫描发现 `sub_10056190` **内部**存在 0x28 步长推进:

```asm
0x100566a9: add dword ptr [esp + 0xcc], 0x28     ; in sub_10056190
```

配合批 5 已知的 `sub_10056603` 区块(循环上限 `cmp eax,0Ah; jge`,即最多 10 次迭代)。

### 5.2 重新审视 `n` 的来源

批 5/7 的推理链是:

```
n = iterB._Myptr->+0x08
result = (W->m[4]).begin() + n          ← sub_1003f0d0
[result._Myptr + 0x90] = 1              ← 写状态码
```

**但从未验证 `iterB` 迭代的是哪一个 vector。** 于是提出假设:
若 iterB 迭代的是 `W->m[5]`(0x28 元素),则 `n` 是 0x28 记录的字段,而非 0xA0 元素的字段。

### 5.3 ⚠️ 该假设**未能证实**(如实记录)

核查 `sub_10056190` 中对 0x28 迭代器 `sub_1006a860` 的两处调用:

| 调用点 | 迭代器对象帧偏移 |
|---|---|
| `0x1005a480` | **−648**(`[esp+0xd4]` 写入,`[esp+0xd0]` 取址) |
| `0x1005a4c5` | **−648** |

而 iterB 位于帧偏移 **−808/−804**。**两者不是同一个迭代器。**

**因此:「iterB 迭代 0x28 vector」的假设被削弱,不予采信。**

### 5.4 仍然成立的结论

尽管上述假设未证实,以下事实**独立成立**:

1. **`sub_10056190` 确实同时迭代两种步长** —— 0xA0(iterA,帧 −772/−768,经 `sub_1003d720`)
   与 **0x28**(帧 −648,经 `sub_1006a860`)。引擎是**双步长**的。
2. **`+0x04`/`+0x08` 在 0xA0 元素上无任何写入**(批 7 穷举 `mov` + 批 8 穷举算术指令,双重确认)。
3. 因此 `n` 的来源只可能是:
   - **(a)** 0xA0 元素以外对象(如 0x28 记录)的字段;
   - **(b)** 由**批量拷贝**(`rep movsd`,来自公式引擎的输入数据)带入的字段。

> **结论:原问题「0xA0 元素的 `+0x04`/`+0x08` 是 0 基还是 1 基」的提法很可能有误 ——
> 该字段或许根本不属于 0xA0 元素。**

## 九、方法论备忘(重要)

1. **递归下降 ≠ 万能**:不覆盖跳转表目标。存在性结论必须**线性扫描 + 递归下降交叉验证**。
2. **扫描必须包含算术指令**:`add dword ptr [reg+off], imm` 是 vector `_Mylast` 运算的典型形态,
   只扫 `mov` 会漏。本批正是靠扩展指令类才发现 §4。
3. **栈槽必须换算帧偏移**:源报告 `[esp+X]` 是当前-esp 相对(批 7 已证)。
4. **栈跟踪需处理多出口函数的 `ret N`**:否则跨大范围会出现累积漂移(本批仍未完全消除)。
