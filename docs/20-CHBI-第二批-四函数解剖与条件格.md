## 〇、摘要（结论先行）

1. **四个函数都是「同构笔族」的零件**，全部作用于同一个对象 **W**（= `*ctx`，即 CalcProc 惰性句柄 `[this+0xB0]` 所指的层级对象）：
   - `0x1003db40` = **候选端点生成器**：逐 bar 扫描 (H,L)，把「准极值」写成一个 **0xA0 元素**追加进 `W->m0`；
   - `0x1003e200` = **严格分型标注器**：对 `W->m0` 每个内部元素，比较其前后邻居 → 写 `元素.+0x14 = ±1`（顶/底）；
   - `0x1004b1e0` / `0x1004f430` = **一对镜像孪生**的「笔端点定向/收敛器」（条件形状序列 **98.8% 逐位一致**，仅末位 1 处边界差异）。
2. **P 参数就是分派开关**（本批新发现，修正 docs/18 的"两段同构块"表述）：
   `P=11/12 → 0x1003f170`、`P=21/22 → 0x1004b1e0`、`P=31/32 → 0x1004f430`、`P=51 → 0x1006a040`；偶数/奇数（= 2/1）对应「底/顶」两种扫描方向。
3. **0xA0 元素模板被完整还原**（`0x1003db40` 在栈上 `[esp+0x40..0xDF]` 逐字段填好后 `push_back`，等于原始结构体明文）。
4. **两个大函数尾部把 `0x28` 元素的方向标志传播回 `0xA0` 元素的 `+0x20`**：`A0[idxA].+0x20 = +1`、`A0[idxB].+0x20 = -1` —— 即「笔」的有向端点标注。
5. **勘误**：既有 `extract_x87_conditions.py` 的解码表有 3 条与 Intel 语义不符（`0x41/je`、`0x41/jp`、`0x41/jnp`），本批修正并重生成 CHDUAN 证据（docs/17 的手写表原本就是对的）。
6. 残留：两个大函数各 3/5 处基本块栈态分歧、`0x28` 元素布局与 docs/16 记载存在偏移差异 → 均登记待仲裁（§9）。

## 一、工具与勘误（本批基础设施）

### 1.1 `x87_sim.py`（新建，替代 v1 用于本批）

v1（`extract_x87_conditions.py`）只做"最近两次 `fld` + `fcompp`"的直线配对，**不模拟 x87 栈**，遇到
`fxch st(3)`、`fcom st(2)`、`fstp st(1)` 这类栈重排就会把操作数认错，分支汇合处还会串味。

v2（`x87_sim.py`）改为 **基本块级数据流模拟**：

- 以「跳转目标 / 跳转后一条」切基本块，对每块做 x87 寄存器栈（ST0 = 栈顶）模拟；
- 出块栈态沿后继边传播（worklist），多前驱栈态不一致时标记 `conflicts`；
- 逐条维护 `fld / fldz / fst / fstp(st(i) 或 mem) / fxch / fcom(p) st(i) / fcompp / fucom(p) / 算术 / 一元`；
- 每个比较点输出**真实操作数来源**（`ST0` vs `ST(k)` 或 `mem:`）+ `test ah,mask` + `jcc` + 四态解码。

自检：`python x87_sim.py --selftest` → `selftest OK (10 cases)`（10 组 mask/jcc 真值断言）。
可复现命令见 §8。

### 1.2 勘误：x87 四态真值表（v1 解码表 3 条错误）

## 二、共用底座：W 对象与 0xA0 元素模板（本批硬成果）

### 2.1 W 的容器布局（实测）

四个函数的 arg1 都是 W（`0x1002c1d0` 里 `mov eax,[esp+0x3c]; mov edi,[eax]` → `edi = *ctx`）。W 内嵌两个 `vector`：

| W 偏移 | 内容 | 依据 |
| --- | --- | --- |
| `+0x00/+0x04/+0x08` | **`m[0]`**：`+0x04=begin`, `+0x08=end`，**元素步长 0xA0** | `mov edi,[ebp+4]; mov esi,[ebp+8]; sub esi,edi; /0xA0`（`0x1003db40` 序言） |
| `+0x50/+0x54/+0x58` | **`m[5]`**：`+0x54=begin`, `+0x58=end`，**元素步长 0x28** | `lea eax,[edi+0x50]` / `cmp ebp,[edi+0x58]` / `add ebp,0x28`（大函数尾部）；与 docs/16 §2.1「m[5] @+0x50 = 0x28 项」一致 |
| `+0x88/+0x8C/+0x90` | 三个 int 计数器 | `0x1004b1e0` `0x1004f430` `0x1003f170` 序言统一清零 |

> 即 W 结构 = `{ VectorMember m[8] @0x00/0x10/…/0x70; …; int cnt[3] @+0x88 }`（与 `pseudocode/chduan.c` 的模型、docs/06 一致）。
> 本批只用到 `m[0]`（0xA0 笔元素）与 `m[5]`（0x28 笔记录）。

### 2.2 **0xA0 元素模板**（`0x1003db40` 栈上逐字段填充 = 结构体明文）

`0x1003db40` 在 `lea eax,[esp+0x40]` 处构造元素（恰好占 `[esp+0x40..0xDF]`＝0xA0 字节），再 `push_back`：

| 元素偏移 | 类型 | 本批观测到的写入 | 语义（推断） |
| --- | --- | --- | --- |
| `+0x00` | int | `[esp+0x40] ← edi`（当前 bar 序号） | **bar 索引**（与 docs/15 CHDUAN 的 `out[item[+0x00]-1]` 口径一致） |
| `+0x04` | f32 | 0 | 待定 |
| `+0x08` | f32 | 0 | 待定 |
| `+0x0C` | f32 | ← `H[i-1]`（`[esp+0x14]`） | **该 bar 高（来自 srcA/H）** |
| `+0x10` | f32 | ← `L[i-1]`（`[esp+0x18]`） | **该 bar 低（来自 srcB/L）** |
| `+0x14` | int | 0；后被 `0x1003e200` 写 ±1 | **分型类型**（`+1`=顶, `-1`=底） |
| `+0x18` | f32 | 0 | 待定 |
| `+0x1C` | int | ← `ebx`（方向状态变量） | **方向码** |
| `+0x20` | int | 0；后被大函数写 ±1 | **笔方向端点标志**（+1 起点 / −1 终点，§6.4） |
| `+0x24` `+0x28` `+0x2C` `+0x30` `+0x34` | int | 0 | 待定（`+0x24` 与 docs/15 CHDUAN 标记同址） |
| `+0x40` `+0x44` | f32 | 0 → 后 ← 首 bar 的 H/L | 待定（基准） |
| `+0x48` `+0x4C` | f32 | 0 → 后 ← `L[i-1]` / `H[i-1]` | 待定 |
| `+0x50..+0x5C` | f32 | 0 | 待定 |
| `+0x64` `+0x68` | f32 | 0 | 待定 |
| `+0x70` | int | **1**（顶分支） | 候选标志 |
| `+0x84` | int | 0 | 待定 |
| `+0x88` `+0x8C` `+0x90` `+0x94` | int | 0 | 待定 |
| `+0x98` | int | **1**（底分支） | 候选标志 |
| `+0x9C` | int | 0 | 待定 |

> 「语义（推断）」列中 `+0x0C=H / +0x10=L` 是**实测可证**的（写入源就是 H/L 缓冲，且 `0x1003e200` 用同两字段做分型比较）；
> 其余 f32 字段本批未追到消费者，标为待定，**不臆测**。

### 2.3 `0x1003db40` 的方向状态机（`ebx`）

`ebx` 在主循环里取 **{0(初值), 1, 2, −1, −2}**：

- `ebx = 1` 时走 `0x1003dd36` 块 → 若 `H` 未创新低则 `ebp = −1`，`ebx = 1`；否则 `ebx = −1`；
- `ebx = −1`（`or ebp,0xffffffff` 前后）→ 顶/底切换（`0x1003dd15`/`0x1003dd36` 两块）；
- `ebx = 2` / `−2`（`0x1003dcf9`/`0x1003de3b`）→ 「确认一个笔端点」；
- `0x1003db40` 的 `[esp+0xe0]`（候选极值索引）与 `[esp+0x40]`（输出元素 `+0x00`）随状态机推进。

## 三、调用上下文：`0x1002c1d0` 按 P 分派（修正 docs/18）

```
0x1002c1d0(ctx, count, outD, src /*{H*,L*,P*}*/, iface)
  1) bufA/bufB = new[](count*4)
     for k: bufA[k] = (float)H[k];  bufB[k] = (float)L[k];  outD[k] = H[k] (double 原精度)
  2) 0x1003db40(W, count, bufA, bufB)      ; 候选端点生成 → 追加 A0 元素
  3) 0x1003e200(W)                          ; 严格分型标注 (+0x14 = ±1)
  4) P = (int)*src[8]                       ; 0x1006bc70
     switch (P):
       case 11: 0x1003f170(W, 1); case 12: 0x1003f170(W, 2);   // ★ 本批未展开
       case 21: 0x1004b1e0(W, 1); case 22: 0x1004b1e0(W, 2);   // 本批主角
       case 31: 0x1004f430(W, 1); case 32: 0x1004f430(W, 2);   // 本批主角
       default: goto 0x1002c30b
     then 0x1003eba0(W)   ; m[2] 预处理（与 CHDUAN 共用，docs/18）
         0x1003ef00(W)   ; 方向标注（README 关键地址表）
  case 51: 0x1006a040(W); 0x1003eba0; 0x1003ef00;
           iface->vtbl[1](0xEA62)            ; ★ 第二道授权门（0x1002c330）
```

- **修正 docs/18**：docs/18 把 1002c281/1002c55e 称作"两段同构处理块(顶/底)"——实为**同一段代码的两次调用序列**，
  且真正决定顶/底的是 **P 的奇偶**（mode=1 顶 / mode=2 底），不由代码块区分。
- **P 家族已见全貌**：`{11,12}`→`0x1003f170`（8368 指令，最大）、`{21,22}`→`0x1004b1e0`、`{31,32}`→`0x1004f430`、`51`→`0x1006a040`。
  四者序言**完全同构**（都清零 `W+0x88/0x8C/0x90`）→ 同一模板的四个版本。
- **双重授权**：包装层 `0x1000f580` 在 `P==51` 时查 `Authorize(0xEA62)`（docs/15 结论**正确**）；
  工作函数 `0x1002c1d0` 在 P==51 分支**再查一次**（`iface->vtbl[1](0xEA62)`，`0x1002c330`）——**新增发现**。
- `0x1003f170`（P=11/12）本批**未解剖**，登记为下一批首选。

## 四、函数① `0x1003db40` —— 候选端点生成器

### 4.1 入口签名（实测）

```
void __stdcall f_1003db40(W *self, int n, const float *srcH, const float *srcL);
```
- 序言：`sub esp,0x174; push ebx,ebp,esi,edi` → `[esp+0x180]`/`[esp+0x188]` 都是 arg1(W)，`[esp+0x18C]`=arg2(n)，
  `[esp+0x190]`=arg3(srcH)，`[esp+0x194]`=arg4(srcL)；`ret 0x10` = 4 参 stdcall。
- 调用点：`0x1002c281`，参数 `push ecx(=bufB) / push ebx(=bufA) / push ebp(=count) / push edi(=W)`。

### 4.2 控制流概要

```
1. 清空 W->m0：if (size) 0x1003d8a0(memmove) 把 end 收到 begin
2. if (n <= 0) return
3. 初始化：refH/refL = 0；i = 1；dir(ebx) = 0；cand(ebp) = 0；first = 1
4. for (i = 1; i < n; i++):                    // n-1 次，读 H[i-1], L[i-1]
     a = srcH[i-1]; b = srcL[i-1]
     if (first) { refH = a; refL = b; first = 0 }
     if (dir > 0)  { 上行分支（比 [esp+0x2c]/[esp+0x28]，见 §4.3） }
     else          { 下行分支（比 [esp+0x14]/[esp+0x18]） }
     填 0xA0 元素模板（§2.2）：
         elem[+0x00] = i; elem[+0x0C] = a; elem[+0x10] = b; elem[+0x1C] = dir
         ...其余清零；按分支置 elem[+0x70]=1（顶候选）或 elem[+0x98]=1（底候选）
     0x1006a5e0(W, &elem)                       // push_back 到 W->m0（4 个调用点）
5. 尾部（0x1003e00c..）对共享尾块做 ±0.001（0x1006fc28）的微小修正后再 push_back
```

| 11 | `1003e037` | `0.0` vs `ST2=[esp+0x30]` | `ah,44` | `jnp 0x1003e063` | `>`\|`<`\|`U` | **跳转 = 值恰为 0.0**（`fucomp`，0x44 新解码） |
| 12 | `1003e063` | `[esp+0x4c]` vs `ST1=[esp+0x30]` | `ah,05` | `jp 0x1003e08f` | `<` | 尾块二段 |

**条件格（顶/底候选判定骨架）**：

```
上行(H 创新高)  ⟺  refH <= H[i]  且  refL <= L[i]      … 条件 1&2 落空(严格大于)
                    ↘ 再与 H 历史极值 [esi+ebp*4] 比较（条件 3/4）决定候选索引
下行(H 创新低)  ⟺  反之（条件 5/6 走 je=“大于”分支）
尾块微调        ⟺  若 |新−旧| 非零则按 0.001 (=0x1006fc28) 做 ±1 步修正（条件 10~12）
```

> 结论：`0x1003db40` 是**极值候选的粗筛**——只做「相邻 bar 的方向翻转 + 与历史极值比较」，
> 不做严格的「前后都要更低/更高」判定；严格分型判定在 `0x1003e200` 里（§5）。

## 五、函数② `0x1003e200` —— 严格分型标注器

### 5.1 入口签名（实测）

```
void __fastcall f_1003e200(W *self);     // 唯一参数走 EAX：mov ebx, eax
```
- 调用点：`0x1002c288`（`mov eax, edi; call 0x1003e200`，edi = W）。
- 主体：`0x1003f0d0(W, &it, 1)` 取 `W->m0.begin()+1`，再 `esi += 0xA0` 逐元素推进。

### 5.2 控制流概要

```
n = W->m0.size();  if (n <= 1) return
for (i = 1; i <= n-2; i++):              // 只处理"内部"元素
    cur  = m0[i];  prev = cur-0xA0;  next = cur+0xA0
    (curH, curL)   = (cur[+0x0C], cur[+0x10])
    (prevH, prevL) = (prev[+0x0C], prev[+0x10])      // 注意 x87 栈序：ST0=prev 值
    if (prevH < curH && prevL < curL):               // 条件 1&2 落空（严格小于）
        if (i >= n-1) continue
        (nextH, nextL) = (next[+0x0C], next[+0x10])
        if (nextH < curH && nextL < curL):           // 条件 3&4 落空
            cur[+0x14] = +1                          // ★ 顶
    else:
        if (curH < prevH && curL < prevL):           // fxch/复栈后（0x1003e362/36d）
            if (i >= n-1) continue
            if (nextH > curH && nextL > curL):       // 条件 7&8 落空（ah,41 jne 落=“>”）
                cur[+0x14] = -1                      // ★ 底
```

### 5.3 x87 条件链（8 条，全部实测）

| # | 地址 | ST0 vs ST(k) | test | jcc | 跳转成立 | 落空成立 | 语义 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | `1003e2bd` | `prevH` vs `ST1=curH` | `ah,05` | `jp 0x1003e360` | `>\|=` \|`U` | `<` | 落空 = prevH < curH |
| 2 | `1003e2d2` | `prevL` vs `ST1=curL` | `ah,05` | `jp 0x1003e360` | `>\|=`\|`U` | `<` | 落空 = prevL < curL |
| 3 | `1003e32c` | `nextH` vs `ST1=curH` | `ah,05` | `jp 0x1003e3e4` | `>\|=`\|`U` | `<` | 落空 = nextH < curH |
| 4 | `1003e340` | `nextL` vs `ST1=curL` | `ah,05` | `jp 0x1003e3e4` | `>\|=`\|`U` | `<` | 落空 = nextL < curL → **写 +1** |
| 5 | `1003e362` | `curH` vs `ST2=prevH` | `ah,05` | `jp 0x1003e3e0` | `>\|=`\|`U` | `<` | 落空 = curH < prevH |
| 6 | `1003e36d` | `curL` vs `ST1=prevL` | `ah,05` | `jp 0x1003e3e4` | `>\|=`\|`U` | `<` | 落空 = curL < prevL |
| 7 | `1003e3b7` | `nextH` vs `ST1=curH` | `ah,41` | `jne 0x1003e3e4` | `<\|=\|U` | `>` | 落空 = nextH > curH |
| 8 | `1003e3c7` | `nextL` vs `ST1=curL` | `ah,41` | `jne 0x1003e3e4` | `<\|=\|U` | `>` | 落空 = nextL > curL → **写 −1** |

**标记写入**：`0x1003e354  mov [esi+0x14], 1`、`0x1003e3d7  mov [esi+0x14], 0xFFFFFFFF`。

### 5.4 与 `0x1002c1d0` 的关系

- 无条件调用（**不随 P 分派**），紧跟 `0x1003db40` 之后 —— 即「先生成候选元素，再标注分型类型」。
- 它消费的正是 `0x1003db40` 刚写下的 `+0x0C/+0x10`（H/L），并把结果写进 `+0x14`；
  而 `+0x14` 在大函数尾部被读取（`cmp [ebp+0x14],1` / `cmp [ebp+0x14],-1`）→ **构成 `db40 → e200 → 大函数` 的数据流闭环**。

### 5.5 结论

`0x1003e200` 是**严格分型（顶/底）判定器**：`cur` 的 H 与 L **双双**高于（顶，+1）或双双低于（底，−1）
前后两 bar 才标记；任一字段不满足即不标记。等价于

```
顶(i) ⟺ H[i] > max(H[i-1],H[i+1]) ∧ L[i] > max(L[i-1],L[i+1])
底(i) ⟺ H[i] < min(H[i-1],H[i+1]) ∧ L[i] < min(L[i-1],L[i+1])
```
（注：`=` 与 Unordered 一律归入"不标记"侧 —— 由 §1.2 真值表可证。）

## 六、函数③④ `0x1004b1e0` / `0x1004f430` —— 镜像孪生的笔端点定向器

### 6.1 入口签名（实测）

```
void __stdcall f_1004b1e0(W *self, int mode);   // mode ∈ {1,2}；序言 cmp [esp+0x3B4], 1
void __stdcall f_1004f430(W *self, int mode);   // 序言 cmp [esp+0x39C], 1（同一模板，栈帧 0x394）
```
两者序言**逐条同构**：`sub esp,0x39x` → 取 arg1 → `eax=[W+4]` → 清零 `W+0x88/0x8C/0x90` → `[esp+0x98]=3`。

### 6.2 控制流概要（两者一致）

```
1. 若 W->m28（0x28 向量 @+0x50）非空 → 先收缩/清空
2. epb = W->m0.size()（0xA0 步长）
3. 主体：以 0x1003db40 生成的候选元素为输入，做
   - 元素字段读取：一律经 0x1006a830（operator*）+ 断言
   - 三处 x87 比较族：
       * [eax+0x0C]（H） 与 [esp+0x30] / [esp+0xf0]（历史极值栈槽）
       * [eax+0x10]（L） 与同上
       * [0x1006fc50]（常量 −1.0f，哨兵）与 [esp+0x1c]   → fucom/fucomp + ah,44
   - 判「候选是否成立」，成立则 0x100697a0/0x100699c0（b1e0）或 0x10069ba0/0x10069e10（f430）插入 0xA0 元素
   - 0x1006a5e0 / 0x1006a720 / 0x1006a7c0 / 0x1006a890：0x28 向量的 push_back / pop_back / size
4. 尾部（0x1004f1e1..0x1004f399 / 0x10053xxx）：见 §6.4
```

### 6.3 条件格：两函数 **98.8% 逐位同构**（本批最硬证据）

按顺序取出两者 80 条条件的「指令形状（op / ST(k) 下标 / mask / jcc）」序列比对：

```
counts: 80 vs 80 ;  逐位相同 79/80 = 98.8%
第 78 位（末位）差异：  0x41/jp   vs   0x41/jnp
```

这解释了 docs/18 的"顶/底两段同构"：`0x1004b1e0` 与 `0x1004f430` 是**同一算法的两个镜像实例**
（`mode=1` 顶向 / `mode=2` 底向），差异被外提到 `mode` 参数，因此代码近乎逐字节对称；
唯一的结构性差异落在**收尾边界**（末位条件的 `jp` vs `jnp`，即"≥ 或不可比" vs "≥ 严格"）。

调用画像同样对称（见 `cond_*.txt` 的 [C] 节）：

| 被调 | `0x1004b1e0` | `0x1004f430` |
| --- | --- | --- |
| `0x1006a830`（operator*） | 296 | 298 |
| `0x1003f0d0`（begin()+n） | 58 | 57 |
| `0x100697a0` / `0x10069ba0` | 12 | 12 |
| `0x100699c0` / `0x10069e10` | 13 | 13 |
| `0x10069540`（读 +0x14==−1） | 3 | 0 |
| 间接调用（ebx/ebp/esi） | 3 | 7+3 |

### 6.4 尾部：笔端点方向标注（关键语义）

`0x1004b1e0` 尾部 `0x1004f1e1` 起遍历 **`W->m28`（0x28 步长，`[edi+0x54]..[edi+0x58]`）**，
对每个 0x28 元素 E：

```
if (E[+0x14] == 1 || E[+0x14] == -1) {
    A0[E[+0x04]].+0x20 = 1;        // 起点标 +1   （0x1004f2d5 / 0x1004f343）
    A0[E[+0x08]].+0x20 = -1;       // 终点标 −1   （0x1004f381）
} else {
    E[+0x20] = (X - E[+0x08] > [esp+0x98]) ? 1 : 0;   // 0x1004f26f / 0x1004f283
}
```
其中 `A0[idx]` 由 `0x1003f0d0(edi, &it, idx)` 取得（`edi` = W，`ebx` 传容器）。

> **语义**：每个「笔」以一个 **有向端点对** 表示 —— 起点元素 `+0x20=+1`、终点元素 `+0x20=−1`；
> 这解释了 docs/16 中 `+0x24` 类「方向标记」的设计同源（不同函数用不同偏移）。
> `+0x14 ∈ {±1}` 正是 `0x1003e200` 刚写入的分型类型 → **`e200 → 大函数尾部` 数据流闭环再次确认**。

> **待仲裁**：`E[+0x14]==1` 与 `==-1` 两个分支在此尾部的动作**观测上完全等价**
> （都执行 起点 +1 / 终点 −1；仅使用了不同的临时出参槽 `[esp+0x14C]` vs `[esp+0x164]`）。
> 可能原因：① 编译器把两 case 合并；② 原始语义差异落在更早的代码路径上。**不掩盖，登记待仲裁。**

### 6.5 常量语义（实测）

| 地址 | 值 | 用途 |
| --- | --- | --- |
| `0x1006fc50` | `0xBF800000` = **−1.0f** | 哨兵（"未设置"）；`fucom/fucomp … ah,44 jnp(=)` 即"是否等于 −1.0" |
| `0x1006fc28` | `0x3F50624DD2F1A9FC` = **0.001** | 尾块微调步长（`fsub`/`fadd`） |
| `0x1006f194` | `_REPORT_RANGECHECK` 陷阱 | 断言失败即 `call` |
| `0x1006f750` / `0x1006f708` | vtable（`0x1001e390` / `0x10001d90`） | shared_ptr 控制块 / wrapper 回调接口 |

### 6.6 与 `0x1002c1d0` 的关系

- **由 P 分派决定是否调用**：`P∈{21,22}` → `0x1004b1e0(W, 1|2)`；`P∈{31,32}` → `0x1004f430(W, 1|2)`。
  其余 P 值**完全不调用这两个函数** → 二者是 CHBI 的**可选精炼阶段**（对应不同"笔"定义）。
- 调用后必接 `0x1003eba0(W)`（m[2] 预处理）+ `0x1003ef00(W)`（方向标注）→ 供公式侧读取。
