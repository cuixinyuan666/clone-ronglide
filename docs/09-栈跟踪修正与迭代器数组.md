## 二、漂移根因与修复

### 2.1 根因

批 8 的跟踪器用 `eff = 4 + N` 计算 `call` 之后的 esp 变化(`N` = 被调函数的 `ret N`)。**这是错的。**

正确推导:设 `S` 为 `push` 参数前的 esp。

```
push arg      → esp = S-4
call f        → esp = S-8        （压入返回地址）
f: ret 4      → esp = S-8+4+4 = S
```

`delta` 是在 **`call` 指令处**(即压入返回地址**之前**,esp = S-4)测量的。
故 `delta_after = delta_at_call + 4` = `delta_at_call + N`(当 `N = 4`)。

> **修正:`eff = N`,而非 `4 + N`。** 每次调用偏差 4 字节,在数千条指令中累积成 1476 字节的漂移。

### 2.2 修复后的验证(三重)

| 验证项 | 结果 |
|---|---|
| **出口校验** | `0x1005c58a ret 4` → `delta=+0` → `0+4+4=8` ✓;`0x1005cbf3 ret 4` → `delta=+0` ✓ |
| **状态数** | **8173** 个 `(va,delta)` = 与指令数**完全一致**(修复前 200000,状态爆炸) |
| **delta 唯一性** | 8173 个地址中,**0 个**被多个 delta 到达 → 帧偏移无歧义 |

## 三、重大修正:`[esp+0x43C]` 是函数参数

修正后:

```asm
0x10056197: mov ebx, dword ptr [esp + 0x430]   → 帧偏移 E+4   ; 序言读参数
0x1005a120: mov esi, dword ptr [esp + 0x43c]   → 帧偏移 E+4   ; ★ 同一槽!
```

**两处的帧偏移都是 `E+4` = 函数的第一个栈参数。**

> **即:`sub_10056190` 的参数本身就是容器指针**,而 `[esp+43Ch]`/`[esp+430h]` 只是它在不同 esp 水平下的文本表示。
> 这**否定了批 7 的「`[esp+43Ch]` = `W+0x40`」推断**,并**恢复了批 6 的模型**:
> 参数是一个 `std::vector`(其 `+0x04`/`+0x08` 即 `_Myfirst`/`_Mylast`)。

### 3.1 参数容器的元素类型

```asm
0x10056237: mov eax, [ebx+44h]      ; ebx = 参数 … 但见下
```
> ⚠️ 注:此处的 `[ebx+44h]` 需在修正跟踪下重新核对 —— 若 ebx = 参数(vector,16 字节),
> 则 `+0x44` 越界。**该点列入第 10 轮待办**(可能 ebx 已被重新赋值)。

## 四、🔑 核心发现:序言清零的是「受检迭代器数组」

### 4.1 序言清零序列

```asm
0x100561a7: xor edi,edi
0x100561a9..0x100561ed:  mov [esp+0x18]..[esp+0x5C], edi    ; 18 个 dword = 72 字节
0x100561f1..0x10056230:  mov [esp+0xD8]..[esp+0xFC], edi
0x10056243: mov [esp+0xBCh],edi
0x1005624a: mov [esp+0x90h],edi
```

修正后:该 72 字节块位于帧 **E-1056 .. E-988**(`[esp+0x18]` 起,delta = −1080)。

### 4.2 该块被当作「8 字节元素数组」使用

```asm
0x10056a19: lea edi, dword ptr [esp + eax*8 + 0x18]   ; ★ edi = &block[eax]
0x10056a21: mov ecx, dword ptr [edi]
0x10056a23: mov edx, dword ptr [edi + 4]
```

同类站点(共 27 处 `&[esp+0x18]` 取址):

```asm
0x10056af2: lea edi, [esp + eax*8 + 0x18]
0x10056bf1: lea edi, [esp + eax*8 + 0x18]
0x100567ae: lea ebx, [esp + 0x18]            ; 块基址
```

**结论:`[esp+0x18]` 是「8 字节元素的数组」的基址。**

### 4.3 元素的语义 = MSVC 受检迭代器

数组元素为 8 字节 `{_Mycont, _Myptr}`(MSVC `_Vector_iterator`,批 6 已确认)。
对应的标准校验序列:

```asm
cmp  dword ptr [esp+0x40], 0      ; assert _Mycont != NULL
jne  ok
call ebp                           ; _invalid_parameter_noinfo
ok: mov ecx, [esp+0x40]            ; ecx = _Mycont
    mov edx, [esp+0x44]            ; edx = _Myptr
    cmp edx, [ecx+8]               ; _Myptr vs _Mycont->_Mylast
    jb  ok2
    call ebp
```

**且 `[esp+0x40]`/`[esp+0x44]` = 块偏移 0x28/0x2C = 数组的**第 5 个元素**(0x28 ÷ 8 = 5)。**

## 五、🔑 「恒零槽」悖论的解决

### 5.1 悖论回顾

批 7–8 观察到:`[esp+0x40]`/`[esp+0x44]` 在序言被清零后**再无任何写入**(直写扫描、`lea` 取址扫描、
`rep` 批量扫描均为空),却在 **51 处**被当作 `{_Mycont, _Myptr}` 解引用。
由于 `_Mycont = 0`,这些校验必然失败 —— 逻辑上不可能。

### 5.2 真相:**索引寻址写入**

```asm
0x10056a19: lea edi, [esp + eax*8 + 0x18]    ; edi 指向数组第 eax 个元素
0x10056a21: mov ecx, [edi]                    ; 读
0x10056a23: mov edx, [edi+4]
...
lea edi, [esp + eax*8 + 0x18]
mov [edi], X                                  ; ★ 写（经 edi，不是 [esp+0x40]）
mov [edi+4], Y
```

**数组元素是通过「先 `lea` 算出元素地址、再经寄存器写入」的方式赋值的。**

我此前的写入检测只识别**显式 `[esp+X]` 操作数**,因此:
- ❌ 看不见 `mov [edi], X`(edi 来自索引 `lea`)
- ❌ 也看不见被调函数通过指针的写入(如 `lea esi,[esp+0x50]; call sub_1006a830`)

> **这两类写入是「槽位只写一次」假象的来源。没有死代码,是扫描有盲区。**

### 5.3 方法论教训(重要)

| 写入形式 | 直写扫描 | 需补充的分析 |
|---|---|---|
| `mov [esp+0x40], X` | ✅ 可见 | — |
| `lea edi,[esp+eax*8+0x18]; mov [edi],X` | ❌ **盲区** | 索引/别名分析 |
| `lea esi,[esp+0x50]; call f`(f 写 `*esi`) | ❌ **盲区** | 跨过程指针参数分析 |
| `rep movsd`(经 `edi`) | ❌ 盲区 | 字符串指令跟踪 |

**结论:静态扫描只能证明「存在写入」,不能证明「不存在写入」。**
批 7–8 基于"找不到写入者"的推论必须撤回。

**块基址 = `[esp+0x18]` = 帧偏移 E-1056**(delta = −1080 时:0x18 − 1080 = −1056)。
块覆盖 `[esp+0x18]`..`[esp+0x5F]` = 72 字节 = **9 个 8 字节元素**。

|---|---|---|---|---|
| 0 | 0x00 | **E-1056** | `[esp+0x18]` | 块基址(被取址 27 次) |
| 1 | 0x08 | E-1048 | `[esp+0x20]` | — |
| 2 | 0x10 | E-1040 | `[esp+0x28]` | `lea esi,[esp+0x28]` |

| 6 | 0x30 | E-1008 | `[esp+0x48]` | — |

## 九、方法论备忘

1. **`call` 的 esp 修正 = 被调者的 `ret N`**(`delta` 在 call 指令处测量,返回地址尚未压入)。
2. **出口校验是必需的**:`delta + 4 + N_func == 4 + N_func`(即 `delta == 0`)。
3. **状态数应等于指令数**:若远超,说明 delta 传播有误。
4. **每地址 delta 应唯一**:多值意味着模型不完整。
5. **静态扫描无法证明"不存在写入"** —— 索引寻址、指针参数、字符串指令都是盲区。
