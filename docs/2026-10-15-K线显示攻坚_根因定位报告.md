# 融立德《缠中说禅》K线显示攻坚 — 根因定位报告

> 日期：2026-10-15 凌晨
> 分支：`old1`
> 目标：让软件的 K 线图显示出来（服务器已下线的前提下）

---

## 一、最终结论（一句话）

**K线空白不是数据格式问题，而是「数据引擎缺索引」**：软件的数据引擎（`rquo.dll`）靠服务器下发的
「活动内存/静态内存」索引（`Sys/<市场>/ActMem_XX.rs`、`StaMem_XX.rs`、`Dat/Mem/*`）把
「股票代码」映射到本地数据文件。该索引**从未下发**（服务器已死），因此引擎**根本不会去读**任何本地
`Dat/Min/*.min`、`Dat/His/*.his` 文件 —— 把数据文件放对路径、格式再正确，也不会显示。

已用 **atime（文件访问时间）预言机**实测证明：打开图表窗口后，放在 12 个候选路径
（`Dat/Min/{01,02,1,2,SH,SZ,...}/<代码>.min`）与 6 个候选路径（`Dat/His/.../*.his`）的文件
**一个都没有被读取**（访问时间保持不变）。即：**引擎压根没尝试打开它们**。

## 二、已攻克的成果（本次实质进展）

### 1. 原生数据文件容器格式 —— 100% 破解 ✅

融立德所有 `.rs/.min/.his/.ms` 数据文件共用同一套**自描述容器**格式：

```
偏移   类型      含义
+0     u32       头部长度 = 14 + 字段数×6
+4     u16       保留(0)
+6     u16       记录条数
+8     u16       保留(0)
+10    u16       单条记录字节数
+12    u16       字段个数 n
+14    n×6 字节  字段定义表，每项：
                  u16 字段ID
                  u16 (偏移量<<8) | 类型
                  u16 标志(=0x0400)
之后              记录区：条数 × 记录长度，小端
```

**字段类型码**：`12`=日期(u32,YYYYMMDD整数) `13`=时间(u32,HHMMSS整数) `10`=float32 `9`=其他(u32)

**已解码的实例**：

| 文件 | 头长 | 条数 | 记录长 | 字段数 | 字段表 |
|---|---|---|---|---|---|
| `02#600000#1`（沪市股票分钟）| 68 | 58560 | 36 | 9 | 102@0/12, 101@4/13, 104@8/10, 105@12/10, 107@16/10, 108@20/10, 211@24/9, 214@28/9, 225@32/9 |
| `02#000001#1`（沪市指数分钟）| 92 | 58560 | 46 | 13 | 同上 + 额外4字段(id 230/231/254 + 2000) |

即分钟记录 = `[日期, 时间, 开, 收, 高, 低, 量, 额, 保留]`，
字段顺序 **O,C,H,L**（已用 58560 条全量校验：高≥开收、低≤开收，全部通过）。
数据实际为 **2017 全年 1 分钟线**（244 交易日 × 240 分钟 = 58560 条，2017-01-03 ~ 2017-12-29）。

> 交叉验证：该容器格式同时用于 `Sys/<市场>/SymTable.rs`（沪市 7485 只、深市 7830 只股票）
> 与 `Sys/<市场>/SecTable.rs`，逐一符合 `头长 == 14+字段数×6` 的签名 —— 格式判定确凿无误。

## 三、证据链（为什么断定"缺索引"）

1. `rquo.dll` 字符串：`write active memory file %02X`、`%s/ActMem_%02X.rs`、`%s/StaMem_%02X.rs`、
   `%s/ActMem_I_%02X.rs`、`write active memory file %02X`，以及网络侧
   `recv active memory request`、`recv active item memory request`。
2. `RDM_C.dll` 字符串：`parse act memory response package error`、`parse sta memory response package error`
   —— 说明这两个文件的内容**由服务器应答包解析而来**。
3. 文件系统实测：`Sys/01`~`Sys/0B` **均无** ActMem/StaMem 文件；`Dat/Mem/` 空。
4. atime 预言机实测：打开图表后，`Dat/Min/**` 12 个候选、`Dat/His/**` 6 个候选**均未被读取**。
   （唯一被读取的时机是进入「0508」模式时的一次全目录扫描，说明引擎有能力读本地文件，
   只是常规图表路径不会去找它们。）
5. 用户目录 `User/DownloadInfo.dn` 仅 8 字节、`SelfSymbol.xml` 全空 —— 从无成功下载/注册记录。

## 四、可选的后续攻坚路线（按可行性排序）

### 路线 A（最可行）：离线伪造 ActMem/StaMem 索引 —— 需先确定其格式
- ActMem/StaMem 很可能也是**同一套自描述容器**（与 SymTable.rs 同族）。
- 做法：先构造极小样本让软件读（用 atime 预言机验证是否被读），逐字段试错，
  逆向出「代码 → 数据文件」的索引项结构，再批量生成全市场索引。
- 风险：格式未知，试错轮次不确定；但工具链已就绪，单轮验证约 2 分钟。

### 路线 B：自建"假服务器"，让软件正常登录并下发索引
- 分析 `RDM_C.dll` / `rdm.dll` 的网络包结构（`download_history_request_pkt2` 等已找到符号），
  伪造一个最小服务器回应"活动内存/静态内存/符号表/历史数据"请求。
- 风险/成本最高（协议逆向 + 大量试错），但一旦成功可完全复刻原软件功能。

### 路线 C（绕开本软件）：用免费数据源 + 自己的看图程序
- 已建成的 `tools/free-feed/ronglide_free_feed.py`：新浪(日线/5-60分钟) + Eastmoney(1分钟兜底)，
  经代理 `127.0.0.1:19828` 拉取，输出 CSV（实测 600000 日线 6400+ 条正确）。
- 配套：如需看图，可用 matplotlib/Plotly 生成 K 线图（含成交量/MACD），完全绕开已死的融立德。
- 代价：放弃软件内的缠论指标界面。
