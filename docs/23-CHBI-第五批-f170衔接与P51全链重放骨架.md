## §1 f170 衔接关系 [A]

### §1.1 入口签名

`sub_1003f170(W, mode) -> void`；`ret 8`（2 dword 入参；callee 清栈）

调用点 (来自 `core_1002c1d0.txt:91-97`)：
```
P==0x0B (11): push 1; push edi; call 0x1003f170   ; 1002c2c6
P==0x0C (12): push 2; push edi; call 0x1003f170   ; 1002c2d0
```

入参语义：arg1 = edi = W 持有指针（[edi]=W），arg2 = mode ∈ {1, 2}。
- mode=1 → 顶向
- mode=2 → 底向
（与 0x1004b1e0 / 0x1004f430 的 mode 语义对齐 — docs/20 §6 已确认）

### §1.2 反汇编规模

- 11191 insn ｜ 1288 基本块 ｜ 481 条件 ｜ 4 conflicts
- 跨度 0x1003f170..0x1004b1cf（多 ret：10049169 是中间出口，1004b1cf 是最终 ret 8）
- 栈帧：`sub esp, 0x8b4`（2204 字节大栈），prologue 即零 W+0x88/0x90/0x8c

### §1.3 工具调用密度

| 目标地址 | 次数 | 语义（来自 docs/21 §7） |
| --- | --- | --- |
| 0x1006a830 | 1180 | `vector::iterator::operator*` |
| 0x1003d720 | 75 | `iterator++`（步进 0x28） |
| 0x1003d750 | 61 | `iterator--`（步进 0x28） |
| 0x1003f0d0 | 58 | `m0.begin() + idx` |
| 0x1006a720 | 28 | `push_back` 0x28 元素 |
| 0x10069540 | 16 | 读 `+0x14==-1` 判据 |
| 0x1006a890 | 14 | `pop_back` 0x28 |
| 0x1006a7c0 | 13 | `pop_back` 0xA0 |
| 0x1006a680 | 8 | `begin()` |
| 0x1006a8e0 | 6 | `end()` |
| 0x1006a6c0 | 6 | `size()` |
| 0x1006a6a0 | 6 | `empty()` |
| 0x1006a8c0 | 4 | `erase` |

**判断** [A]：f170 **重度迭代 m5 容器**（0x28 元素，1180 次 operator*），主要操作 push_back/pop_back/erase 0x28；
m0 容器只通过 begin+idx 取迭代器。它**不像 db40 那样做候选端点生成**，而是**对已存在的 m5 记录做方向化分类与剔除**（与 e200 配合）。

### §1.4 尾块 [A]

清空 m0 所有元素 `+0x20 = 0`（迭代器检查回调 `0x1006f194`），然后 `ret 8`。
即 f170 **改写 m0 端点戳**（与 a040 / eba0 / ef00 同构）。

## §2 docs/22 #4 仲裁：H_max/L_min 不更新 [A]

**f170 的工具调用分布确认**：
- **不调用** 0x1003d8a0（m5 区间擦除）—— 表明 f170 不清 m5，只遍历/重写。
- **不调用** db40 路径上的 `[esp+0x28/0x2c]` 写点——H_max/L_min 在 f170 内不更新（且本就是 db40 栈帧局部状态，跨函数不共享）。
- **零初始化 W+0x88/0x90/0x8c**（f170 prologue）—— 这三个槽是 f170 私有，不与 db40 共享。

**结论** [A]：
- H_max/L_min 不更新是 **db40 自身的实现选择**（0 作为初始下界，触发候选靠单边比较 cond 17-25）。
- 该设计把"方向判定"推到 f170 / b1e0 / f430 三个大函数里。
- docs/22 §3 表格的"ebx>0 / ebx<=0 路径"在 P=11/12 时**不执行**——dispatcher 跳过 db40 后的 cond 分流直接到 f170；P=51 时 db40 的 ebx/cond 1-16 也不活跃（走 a040/eba0/ef00 共用后处理）。
- **docs/22 §3.1-3.3 表格是 P=21/22/31/32 专用语义**。

仲裁 #4 关闭。docs/22 §7 第 #4 项标 [A]。

> ⚠️ **2026-10-18 复核更正（本条仲裁作废）**：① `sub_1003db40(W,count,srcH,srcL)` 无 P 入参（§1.1 自证），ebx/cond 1-16 分流由数据驱动、对任何 P 都执行，"P=21/22/31/32 专用"无依据；② "db40 主循环内 H_max/L_min 始终 0.0" 的前提已被证伪——`f_1003db40.txt:296-298` 每轮模板重填块 `fst [esp+0x2c]←H_k`、`fst [esp+0x28]←L_k`，两槽实为上一 bar H/L 追踪槽，code 每轮更新。**仲裁 #4 重开**，证据与影响见 `docs/22 §9`。

## §3 P=51 全链重放骨架 [A]

文件: `tools/wnmr_py/chbi.py`

链路（按 docs/20/21/22 [A] 结论）：
```
sub_1002c4b0(series, ctx, count, outD, iface):
  → db40_replay(w, H, L)              ; 候选端点生成
  → e200_replay(w)                    ; 严格包含分型 (+0x14=±1)
  → a040_replay(w)                    ; 分型笔记录生成 (m5 容器)
  → eba0_replay(w)                    ; 按方向拆 ContA(W+0x20)/ContB(W+0x30)
  → ef00_replay(w)                    ; 全量复制 ContC(W+0x40)
  → iface_authorize_ok 检查           ; 第二道 EA62 授权门
  → output_ring(w, count)             ; out[elem.bar-1] = elem.endpoint × (×2 if +0x98)
```

执行: `python tools/wnmr_py/chbi.py --selftest`

selftest 结果（4/4 通过）：
```
[OK] selftest: out = [0.0, 0.0, 2.0, -2.0, 0.0, 0.0]
[OK] selftest: EA62 deny returns None
[OK] selftest: count=0 returns None
[OK] selftest: A0Elem round-trip OK (160 bytes)
```

**简化说明** [B]：chbi.py 的 db40 / a040 是简化版：
- db40 单边 H 触发（实际 fcom + cond 17-25 全套需更多状态）
- a040 仅按"每对相邻 ±1 元素生成一条"简化（实际有"借用栈槽"语义、计数器从 2 起等细节）
- eba0/ef00 端点戳用同一份 dict 模拟（实际 W 容器分 3 段）

**预期与真实软件差异** [C]：100% 字节级还原需要 1180 次 operator* 循环的完整解码，**本批不做**。
