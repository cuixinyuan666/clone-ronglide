## 二、bar 字段语义(第 1 项)

### 2.1 ⚠️ 关键前提:各构造函数的 bar 基址**不同**

先用「`call 0x1006a720` 前的 `lea eax,[esp+X]`」定位各函数的 bar 基址:

| 函数 | bar 基址 | 备注 |
|---|---|---|
| `sub_1003e410` | `[esp+0x38]` | ✓ 已验证(round 11) |
| `sub_1003e6c0` | `[esp+0x38]` | |
| `sub_1003e930` | `[esp+0x38]` | |
| **`sub_1003eba0`** | **`[esp+0x40]`** | ← 与前三者不同 |
| **`sub_1003ef00`** | **`[esp+0x30]`** | ← 不同 |
| `sub_1003f170` 等 | `[esp+0xCC]` / `[esp+0xC0]` / `[esp+0xBC]` | 另一组 |

> **这推翻了「用统一 `[esp+0x38]` 映射」的做法** —— 必须按函数换算,否则字段归属会整体偏移。

### 2.2 修正后的字段写入表

| 偏移 | `sub_1003e410`(基址 0x38) | `sub_1003e6c0`(0x38) | `sub_1003e930`(0x38) | `sub_1003eba0`(基址 0x40) |
|---|---|---|---|---|
| **+0x00** | `eax` | `eax` | `eax` | `edx` |
| **+0x04** | `esi` | `esi` | `esi` | `级别对象->+0x04` |
| **+0x08** | `[esp+0x14]`(0 基索引) | `edx` | `edx` | `eax` |
| **+0x0C** | `edi->+0x0C` (float) | — | — | `edi->+0x0C` (float) |
| **+0x10** | `ebp->+0x10` (float) | — | — | `edi->+0x10` (float) |
| **+0x14** | — | `ecx` | `ecx` | `1` |
| **+0x18** | `1` / `0xFFFFFFFF` | `ecx` | `eax` | `0` |
| **+0x1C** | — | — | — | `ecx` |
| **+0x20** | — | — | — | `0` |
| **+0x24** | — | — | — | `ecx` |

### 2.3 已确定的语义

| 偏移 | 语义 | 证据强度 |
|---|---|---|
| `+0x0C` | **LOW**(级别对象低点) | 强 —— 4 处均为 `fld [级别对象+0x0C]` → `fstp [bar+0x0C]` |
| `+0x10` | **HIGH**(级别对象高点) | 强 —— 同上,源为 `+0x10` |
| `+0x00` | **1 基序号** | 强(round 11) |
| `+0x08` | **0 基索引**(→ `W->m[0]`) | 强(round 11) |
| `+0x18` | **状态/方向标志**(值域 `{0, 1, −1}`) | 中 —— `sub_1003e410` 写 `1`/`−1`,`sub_1003eba0` 写 `0` |
| `+0x14` | 整数标志(观测值 `1`;另处为 `ecx`) | 弱 |
| `+0x1C` | 整数(`ecx`;另处 `esi`/`−1`) | 弱 |
| `+0x20` | 观测恒为 `0` | 弱 |
| `+0x24` | 整数(`ecx`/`edx`) | 弱 |

### 2.4 ✅ 关键补测:这些字段**是否被引擎读取**

对两个引擎做「访问偏移全集」统计(含十进制位移),结果:

| 引擎 | 访问的全部偏移 |
|---|---|
| `sub_10056190`(主引擎) | `+0x04` `+0x08` `+0x0C` `+0x10` `+0x14` `+0x20` `+0x40` `+0x44` `+0x48` `+0x88` `+0x90` `+0x94` |
| `sub_10060c00`(同族引擎) | `+0x04` `+0x08` `+0x0C` `+0x10` `+0x40` `+0x44` `+0x48` `+0x88` `+0x90` `+0x94` |

> **`+0x18`、`+0x1C`、`+0x24` 在两个引擎中均不出现 → 从未被读取。**
> (`+0x14`/`+0x20` 虽被访问,但那是**级别对象**的字段 —— 见批 5 的 `+0x14` 过滤器与 `+0x20` 方向标志。)

### 2.5 诚实结论

**bar 的 `+0x14`…`+0x24` 的语义未能完全命名,但对本指标的复刻无影响。**

理由:

1. `+0x18`/`+0x1C`/`+0x24` **从未被任何引擎读取** → 纯内部状态,不影响信号判定。
2. `+0x14` 在不同构造函数中被写入 `1` 或 `ecx`;`+0x18` 被写入 `{0, 1, −1}` —— 属**状态标志位**,
   需结合上层状态机才能命名,而该状态机不参与本指标的买卖判定。
3. `+0x20` 观测恒为 `0`。

> **结论:复刻本指标时,bar 只需实现 `+0x00`、`+0x04`、`+0x08`、`+0x0C`、`+0x10` 五个字段;
> `+0x14`…`+0x24` 可略去。** 这使 bar 的复刻规格**完备**。

## 三、哨兵 `N` 的处理(第 2 项)

### 3.1 引擎**不存储**元素个数

序言计算 N 后**并未保存**:

```asm
0x1005625a: mov eax, dword ptr [ebx + 0x44]    ; W->m[4]._Myfirst
0x1005625d: cmp eax, edi
0x1005625f: je 0x1005cbe9                       ; 空 → 直接返回
0x10056265: mov ecx, dword ptr [ebx + 0x48]     ; _Mylast
0x10056268: sub ecx, eax
0x1005626a: mov eax, 0x66666667
0x10056271: sar edx, 4                           ; ÷40
0x10056274: mov eax, edx
0x10056276: shr eax, 0x1f
0x10056279: add eax, edx                         ; eax = N
0x1005627b: je 0x1005cbe9                        ; N==0 → 直接返回
```

**N 只用于「是否为空」判断,未写入任何变量** → 引擎**不可能**做 `n == N` 的显式哨兵比较。

### 3.2 兜底机制:受检迭代器范围断言

每个状态码写入前都有标准范围校验:

```asm
;; 以 0x1005a1fa(状态=1)为例
0x1005a1e3: call 1003F0D0h          ; result = W->m[0].begin() + n
0x1005a1e8: mov ebx, [eax]          ; result._Mycont
0x1005a1ea: test ebx, ebx
0x1005a1ec: mov esi, [eax+4]        ; result._Myptr
0x1005a1ef: jne 0x1005a1f3
0x1005a1f1: call ebp
0x1005a1f3: cmp esi, [ebx+8]        ; ★ _Myptr vs _Mylast
0x1005a1f6: jb  0x1005a1fa          ; 严格小于才继续
0x1005a1f8: call ebp                ; 否则 _invalid_parameter_noinfo
0x1005a1fa: mov dword ptr [esi+0x90], 1
```

**若 `n == N`,`begin()+n` 得到 `end()`,`cmp _Myptr,_Mylast` 不满足 `jb`,即走 `call ebp`。**

### 3.3 ⚠️ 遗留风险(如实记录)

`ds:[1006F194h]`(MFC80U ORDINAL 764)在 **Release 构建下通常为空操作**,
`call ebp` 返回后代码仍会执行 `mov [esi+0x90], 1` —— 而 `esi == _Mylast`,
即**向 vector 尾后写入 4 字节**。

两种可能:

| 可能 | 说明 |
|---|---|
| **(a)** 哨兵 bar 永不被引擎的买卖块使用 | 最可能 —— 哨兵仅出现在「无前驱」的 bar 上,而买卖判定需要前驱 |
| **(b)** 存在越界写(潜在缺陷) | 需动态验证方能排除 |

**结论:引擎侧无显式哨兵过滤,依赖范围断言兜底;该断言在 Release 下不阻断写入。**
这是本指标复刻时需要**显式处理**的一处:复刻时应对 `n >= N` 直接跳过。

## 四、4 组实例的 block 下标(第 3 项)

### 4.1 扫描结果

以「状态码写入点 ← 最近的前置 block 索引读取」关联,得到:

| 实例 | 卖出段(4/5/6)所用 block | 买入段(1/2/3)所用 block |
|---|---|---|
| ① `0x10057c20` / `0x1005a1fa` | 5, 5, 7 | 5, 5, 5 |
| ② `0x10058336` / `0x1005a85c` | 5, 5, 7 | 5, 5, 7 |
| ③ `0x1005b737` / `0x1005bcd4` | 5, 5, 7 | 7, 7, 5 |
| ④ `0x1005c47a` / `0x1005cae3` | 5, 5, 7 | 5, 5, 7 |

**结论:4 组实例使用的 block 下标高度一致(集中在 5 与 7),并非以 block 下标区分。**

### 4.2 block[0..8] 的使用分布

| 索引 | 访问次数 | 首次使用地址 |
|---|---|---|
| 0 | 280 | `0x1005682e`(填充循环的基址) |
| 1 | 20 | `0x10058687` |
| 2 | 288 | `0x10056846` |
| 3 | 62 | `0x10056fb5` |
| 4 | 136 | `0x10056986` |
| **5** | **198** | `0x10056fd7` |
| 6 | 205 | `0x10056a39` |
| **7** | **207** | `0x10057ac3` |
| 8 | 182 | `0x10056b12` |

**9 个索引全部被使用**,且分布均匀 —— 说明「9 个 bar 的滑动窗口」是**逐位使用**的
(每个索引对应不同的比较位置),而非只用一个。

### 4.3 那么 4 组实例究竟差在哪?

结合前批结论,差异在:

| 维度 | 是否区分 4 组 |
|---|---|
| block 下标 | ❌ 不区分(均用 5/7) |
| **临时迭代器缓冲区**(`lea esi,[esp+XXXh]`) | ✅ 每组不同(32Ch/1ECh、3BCh/284h、394h/354h、384h/3B4h) |
| **级别类型过滤器 `+0x14`** | ✅ 每组按 `+0x14 ∈ {1,−1}` 分支 |

> **修正批 5 的表述**:4 组实例是**同一算法的 4 次内联展开**,差异仅在**临时缓冲区**与
> **`+0x14` 过滤分支**,**不在 block 下标**。

## 五、x64dbg 动态验证方案(第 4 项,需本机执行)

### 5.1 环境准备

1. x64dbg(**32 位版** `x32dbg.exe`)以管理员身份启动
2. `文件 → 打开` → `D:\a_ronglide\缠中说禅\MainApp.exe`
3. 菜单 `选项 → 设置 → 事件` 勾选「系统断点」(TLS/Entry)
4. 运行到主程序后,加载一份含「无脑买入线段」指标的 K 线图

### 5.2 关键断点

| # | 地址 | 目的 |
|---|---|---|
| 1 | `TAFLib.dll:0x1005a1fa` | **状态码 1(买入结构起点)写入点** |
| 2 | `0x1003f0d0` | `begin() + n` 计算入口(读栈参数 `n`) |
| 3 | `0x1005a117` | 引擎主循环头(观察 iterA) |

> 首次断下需在「模块」窗口确认 `TAFLib.dll` 的基址 —— 若未按默认 `0x10000000` 加载,
> 所有地址需加上 `实际基址 − 0x10000000`。

### 5.3 断点 1 处需记录的表达式

```asm
;; 断在 0x1005a1fa 时:
esi                      ; 目标级别对象地址
dword [esi+0x90]         ; 即将写入的状态码(应为 1)
dword [esi+0x94]         ; 价格
dword [esi+0x88]         ; 分型标志
;; 参数容器(帧 E+4):
dword [esp+0x43c]        ; = W
dword [[esp+0x43c]+0x44] ; W->m[0]._Myfirst
dword [[esp+0x43c]+0x48] ; W->m[0]._Mylast
;; 迭代器窗口 block[5](帧 E-1016):
dword [esp+0x40]         ; block[5]._Mycont(应为 &W->m[4])
dword [esp+0x44]         ; block[5]._Myptr (应指向某个 bar)
dword [[esp+0x44]+0x08]  ; ★★ n —— 本项目的核心待验证量
```

### 5.4 待验证清单

| # | 待验证命题 | 判定方法 |
|---|---|---|
| **V1** | **`+0x08` 为 0 基** | 取 `n = [[esp+0x44]+0x08]`,再算 `W->m[0]._Myfirst + n*0xA0`,与 `esi` 比较 —— **应相等** |
| V2 | `+0x00` 为 1 基 | 检查 `W->m[0]` 首个元素的 `+0x00` 是否为 1 |
| V3 | 哨兵 `n == N` 是否出现 | 在 `0x1005a1f8`(`call ebp`)下断点,观察是否命中 |
| V4 | `+0x14`…`+0x24` 是否被引擎读取 | 在 `sub_10056190` 内对 `[esi+0x14]`…`[esi+0x24]` 下硬件读断点 |
| V5 | bar 与级别对象的对应关系 | 对比 `[[esp+0x44]+0x0C]` 与该 bar 指向的级别对象的 `+0x0C` |

### 5.5 V1 的具体算式(最关键)

```
n        = dword [[esp+0x44] + 0x08]
base     = dword [[esp+0x43c] + 0x04]        ; W->m[0]._Myfirst
expected = base + n * 0xA0
esi      = 实际目标对象
```
**若 `expected == esi` → 0 基得证;若 `expected == esi + 0xA0` → 说明为 1 基(需修正)。**

## 八、复刻规格摘要(可直接实现)

```c
/* ── 级别对象（W->m[0]，0xA0 字节，0 基下标）── */
typedef struct LevelObj {
    int32_t index;      /* +0x00 1 基序号 → 输出 out[index-1] */
    int32_t idxA;       /* +0x04 前一顶点索引 */
    int32_t idxB;       /* +0x08 后一顶点索引 */
    float   low;        /* +0x0C */
    float   high;       /* +0x10 */
    int32_t levelType;  /* +0x14 分型方向选择器（1 / -1） */
    /* +0x18 未用 */
    int32_t direction;  /* +0x20 方向（1 / -1 / 0） */
    /* +0x24..+0x84 未用 */
    int32_t fractal;    /* +0x88 分型（1 顶 / -1 底） */
    int32_t signal;     /* +0x8C 信号标志 */
    int32_t status;     /* +0x90 ★ 状态码 1..6 → VAR5 */
    float   price;      /* +0x94 ★ 价格 → VAR6 */
} LevelObj;

/* ── 输入 bar（W->m[4]，0x28 字节 POD）── */
typedef struct Bar28 {
    int32_t serial;     /* +0x00 1 基序号 */
    int32_t f04;        /* +0x04 索引 */
    int32_t pos;        /* +0x08 ★ 0 基索引 → W->m[0] 下标 */
    float   low;        /* +0x0C */
    float   high;       /* +0x10 */
    uint8_t _unused[0x14];   /* +0x14..+0x27 引擎不读取 */
} Bar28;

/* ── 判定核心（每个买卖块）── */
void judge(const Bar28* bar, LevelObj* objs, int N)
{
    int n = bar->pos;
    if (n < 0 || n >= N) return;        /* ★ 复刻时显式跳过哨兵（原实现依赖断言） */
    LevelObj* t = &objs[n];             /* = begin() + n，0 基，无需 ±1 */

    if (bar->high < t->low) {           /* 区间不重叠 → 买入组 */
        t->status = 1; t->price = t->high;
        t->status = 2; t->price = t->high;   /* 买入价 */
        t->status = 3; t->price = t->high;   /* 止损价 */
    }
}
```
